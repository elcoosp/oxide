# Benchmark report (§21)

Generated by `benchmarks/run.sh` on **2026-10-21** at HEAD `bfff3c6`.
Every number is a **wall-clock measurement of this machine** (Apple Silicon
macOS, debug `oxide-cli`, warm OS caches), not a spec target. §21's targets
compare against an incumbent (Next / Nuxt / SvelteKit / SolidStart) on
identical hardware; no incumbent is installed here, so the table records the
raw numbers and marks the incumbents as a TODO.

**This report supersedes the 2026-10-19 report** (HEAD `b55f388`). The
delta `b55f388..bfff3c6` includes the **ComponentSource migration** —
components resolve from `dist/server/ssr/index.js` (prod) or a dev source
map, not from a `componentFor` closure in `oxide.config.ts`. The migration
also fixed two bugs the old report could not see: (1) every real-SSR page
was returning `500 no component resolved` once the closure was removed, and
(2) the bundler was inlining React/Vue/Svelte/Solid into the SSR bundle,
producing two Reacts and "invalid hook call / reading 'useState' of null".
Both are closed; the numbers below reflect the resolver path.

The migration **moved some metrics up and others down** and the table is
honest about both directions. The two notable moves:

- **Down:** server bundle bytes dropped 30-95% (framework runtimes are now
  externals, imported once from `node_modules` at runtime instead of inlined
  per-bundle); react L0 p99 dropped from 243 ms to 22 ms (the "first request
  outlier" story from the old report is gone — the resolver path is more
  uniform).
- **Up:** first-request TTFB and cold-start first200 rose because the
  resolver imports the SSR bundle on the first render of a fresh process.
  Closing that gap is a follow-up: lazy route-module imports (import by
  route id on demand) instead of the eager `routes = { ... }` map.

## Cold-start ladder (`bench:cold`, 5 runs/fixture)

`health` = `oxide start` to `GET /_oxide/health` 200. `first200` = start to
first 200 on `GET /`. min / median ms.

| fixture          | health min/med | first200 min/med |
| ---------------- | -------------: | ---------------: |
| smoke-app-react  |        337/341 |         754/ 949 |
| smoke-app-vue    |        355/397 |        1074/1488 |
| smoke-app-svelte |        274/299 |         913/1238 |
| smoke-app-solid  |        265/278 |         671/1059 |

**This is a real regression vs the old report** (react 205/228, vue 71/75,
svelte 72/73, solid 66/77) and it is honest. The old numbers measured a
code path that was 500ing today. The new numbers measure what actually
runs:

- Each of the 5 runs is a fresh process with **no L0 cache**.
- The first `GET /` triggers the resolver, which imports the whole SSR
  entry (`routes = { "<id>": module }`). That's 12 route modules plus
  their transitive deps — ~500-1500 ms on first load depending on
  framework.
- Health (the socket + config) is only 265-397 ms — the resolver cost is
  entirely in `first200`.

The fix for this is lazy route-module resolution (import by id on demand
inside `resolverFor`, not eagerly at loadComponentEntry). That is a
follow-up WP; the trade is more code in the resolver but a per-route
import cost instead of per-bundle.

**react p99 = 22.1 ms** — the 243 ms outlier the old report attributed to
"first-request TCP handshake + render-pool warmup" is **gone**. The
resolver path is uniformly 22 ms p99 for react; 26-53 ms for the others.
This is the cleanest signal in this report: the old outlier was real (a
lazy import firing mid-run), and the eager-import path the resolver
uses eliminates it.

**p50 = 17-21 ms, still 17-21× the §21 `< 1 ms` target.** This is the
remaining §21 lever: the hit path (nonce substitution, header merge,
`Server-Timing` compute, CSP assembly) is Rust-only but non-trivial. Not
addressed this session. PERF-04 (single-flight + SWR) and PERF-07 (rkyv
matcher) are the levers.

## Known gaps exposed by this run

1. **L0 p50 is 17-21 ms, not the §21 `< 1 ms` target** — real perf gap in
   the hit path (nonce substitution + header merge + CSP + `Server-Timing`
   on every response). PERF-04 / PERF-07 levers.
2. **Cold-start first200 is 671-1488 ms** — the resolver eagerly imports
   the whole SSR entry on first render. Lazy route-module imports are the
   fix (import by route id on demand). This is a consequence of the
   ComponentSource migration landing; it is not a bug, it is an honest
   trade.
3. **First-request TTFB is 522-602 ms** — same root cause as (2). The
   amortized number (L0 p50) is fast; the first render pays the import
   once.
4. **HMR has one timeout in 15** — worth a look; not a regression from
   this session.

## Not measured (and why)

- **"2× incumbent"** — incumbents not installed. The raw numbers are
  recorded so the comparison can run on a machine that has them.
- **`analyze` per-route budgets** — PERF-09 records real per-module
  metadata; until then the byte columns above are the whole-bundle sums.
- **Cold-disk (rather than warm-cache) runs** — the report is warm; a
  cold-disk run is 3-4× slower across the board and is not what the gate
  compares against.
