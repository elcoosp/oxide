**Product gap — every request is `bypass`, not `L0-hit` or `L0-miss`.**
`mode_is_cacheable(render_mode.as_deref())` returns `true` for `static`
(the server manifest does report `routes/index/page: mode=static`), so
`l0_eligible` should be `true` — but the served header is `bypass`, which
means either (a) the in-memory `RouteTree` the dispatch sees has
`render_mode = None` because `refine_render_modes_from_ast` was not run at
`start` time, or (b) a code path earlier than the L0 put/lookup short-circuits
to a static-asset handler that writes `bypass` without touching L0.

Either way, the §21 target ("L0 cache hit p99 < 1 ms") is **not measurable
today** because nothing hits the L0 path. That is a real correctness gap in
the L0 enabling logic, not a harness artifact — the previous report showed
168 hits for react on a stale `dist/`, so the pipeline *can* hit L0; this
build's tree does not have the right state. Tracked as an open §11 item.

## HMR (`bench:hmr`, smoke-app-react)

**Current: 1 / 15 iterations delivered an updated response.** Matches the
previous report's "0 / 8". The dev watcher fires
(`INFO file change ev=Modified(…/page.tsx)`) but the change never reaches
the served HTML within the timeout. This is the known coarse-invalidation
gap: `oxide dev`'s loop calls `invalidate_framework_modules` but does not
re-render the route. SPEC-14 (HMR end-to-end) + PERF-08 (demand-graph
invalidation) close it. The harness is in place; re-run
`./benchmarks/run.sh bench:hmr` after those land.

## Known gaps exposed by this run

1. **`smoke-app-solid` build fails** on a missing `solid-js` peer dep —
   `pnpm install` does not auto-install peers. Fix in CI:
   `.npmrc` with `auto-install-peers=true`, or `pnpm add solid-js@2.0.0-rc.14
   --filter smoke-app-solid --save-exact`. Until then the fixture is
   documented as "unbuildable without a manual peer install".
2. **L0 cache never hits on this build** — every request is `bypass`, not
   `L0-hit`/`L0-miss`. The L0 enabling logic sees a `render_mode = None` in
   the in-memory tree even though the persisted manifest reports `static`.
   Tracked as an open §11 item; the harness is correct, the pipeline is not.
3. **HMR delivers 1/15** — the dev watcher invalidates modules but does not
   re-render. SPEC-14 / PERF-08 territory.
