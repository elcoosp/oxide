## Findings worth naming

- **React's warm build is slower than its cold build.** 5664 ms cold
  versus 6365 ms warm, on a machine where the second run changed nothing.
  A warm build should be a fraction of a cold one — this is a real
  regression to investigate, not a measurement artifact. The likely cause
  is that `oxide build` re-runs the full bundler every time; there is no
  persistent build cache on the path yet (§5's graph engine + CAS crate
  exists but is not wired into `oxide build`).

- **Vue's server bundle is 951 KB.** The other three are 1–40 KB. Vue's
  `@vue/server-renderer` is bundled whole into the SSR entry because
  RolldownBundler treats it as a project dependency (it is not in
  `externals`). This is correct for a self-contained server bundle but
  large; marking Node-built-ins and large framework runtimes external
  would shrink it.

- **Cold start is 782 ms (React) to 2871 ms (Solid).** The spec's target
  is ≤ 50 ms with an app snapshot (§4.4). Snapshots are not implemented;
  the number here is the honest cost of evaluating the bundle from
  scratch, and it is the size of the gap the snapshot feature closes.

## Not measured

- **L0 response-cache hit p99.** No L0 cache on the request path yet
  (§11 gap).
- **HMR p95.** Needs a running dev server plus a scripted edit loop;
  planned as `bench:hmr`.
- **"2× incumbent" comparisons.** Need the incumbents installed; the raw
  numbers are recorded so the comparison can be run wherever they are.
